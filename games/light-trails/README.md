# 光尾蛇 · Light Trails

**控制方向，避开墙壁与光轨，生存至最后。**

- 触屏使用网页右下角的四向虚拟方向键，不受 16:9 赛场边界限制；键盘支持方向键或 `W` / `A` / `S` / `D`，均为绝对方向。
- 自动前进，每格最多转向 90°，连续猛点不能瞬间掉头。
- 撞墙、自己的尾迹或对手的尾迹判负；同时碰撞则平局。
- 三秒倒数，双方确认再来一局，累计比分。
- 支持旁观。短暂断线 / 切后台后暂停，恢复后倒数继续。

## 接入

源码目录为 `games/light-trails/`，开发和部署地址均为 `/light-trails/`。Manifest 使用两人房间、Lua 服务端和 `persistence: "live"`。客户端通信代码位于 `src/playweft-client.js`。

Manifest 顶层设置 `"orientation": "landscape"`，由 Playweft 请求横屏，必要时进入全屏后重试。浏览器可能不支持或拒绝锁定；游戏保留竖屏布局和旋转提示，不在 iframe 内重复申请全屏。实际赛场固定为 16:9，在 iframe 的安全区域内等比放大至宽或高的上限，并在水平、垂直方向居中；不裁剪、不拉伸。比分位于赛场浮层，方向键位于整个网页的安全区域内，不再占据左右栏。适配安全区域、矮屏和减少动画偏好。局内计时来自服务端已执行的步数，暂停时不计时。

界面版本为 `1.3.2`。部署后使用最新 Manifest 创建新房间，以应用横屏偏好和新版资源。

在仓库根目录运行 `npm run dev` 可与真正的 Playweft 平台一起开发；`npm run dev:light-trails` 启动独立开发联调工具。具体地址和构建命令见 [仓库说明](../../README.md)。

## 同步与规则参数

`game.lua` 顶部的 `WIDTH`、`HEIGHT`、`STEP_MS`、`COUNTDOWN_MS`、`STALE_MS` 分别控制地图宽高、前进步长、倒数和断线判定。当前参数是 48×27、120 ms / 格、三秒倒数和 1.8 秒离线阈值。调整地图大小时也需检查 `new_round` 的出生点；客户端从服务器状态读取地图大小和步长，无需单独修改这些常量。

Playweft live room 没有自动 tick，也不能使用 `timerOps`。双方各以 100 ms 间隔提交 `pulse`，每名玩家最多三个 pulse 在途，避免等待网络往返导致发送频率下降；转向单独立即提交。旁观者不发送 pulse。

Lua 按平台 `context.actionAt` 推进固定时间步，不信任客户端时间、坐标或身份。增加 pulse 次数不会加速游戏。先结算已到期的移动，再排队下一步转向，迟到输入不能改写过去。每一步先检查两人的目标格，再一起提交移动，避免座位顺序影响判定。

`steer` 输入携带 `seq`、目标 `tick` 和绝对 `heading`（东 0、南 1、西 2、北 3）。服务端队列最多六项、未来六步，迟到输入顺延，每步最多执行一项；重复序号不会重复转向。自己的视图包含已接收序号、已执行序号和服务器排定的输入队列，对手不可见。暂停会清空队列，重开会重置序号。

客户端最多四个转向请求并发，另有最多三个 pulse。先记录输入并预测自己的光尾蛇，再以每次权威快照为起点，应用服务器队列并重放尚未确认的输入。利用平台 `platform.latency.rttMs` 的半程估计对齐时间，根据延迟最多领先二至四格；遇到已知墙或轨迹停止预测。新快照会立即替换错误轨迹，拒绝输入会移除，重开/切换比赛会丢弃旧请求。显示时钟以最多 10% 的速率调整吸收快照抖动，转向只安排在尚未开始显示的路段，并预留半程网络延迟。对手使用独立、单调前进的播放时间线，按实际推进快照的到达间隔和数据年龄调整 180–480 ms 的缓冲，而非仅按 RTT 固定延后。缓冲变化通过最多 ±15% 的播放速率变化消化，不回退或跳动。快照暂时不足时最多沿已知朝向外推一格，遇墙或已知轨迹停止；碰撞结果仍由服务端确认。快照包含完整轨迹，一包收到多步时也会依次经过拐角。角色移动属于必要反馈，不随系统“减少动画”设置关闭插值。碰撞地图编码为 27 行、每行 48 格的字符串，轨迹使用格子编号数组；`view` 隐藏地图、在线记录和对手尚未执行的转向。

## 已知限制与验证

- 已加入有界本地预测与校正；仅短暂外推对手直行，不预测对手转向，不回溯改判碰撞。对手画面会略微延后，以吸收网络抖动；长时间断网仍会停止显示推进。高延迟或轨迹冲突时可能出现位置校正，最终碰撞和胜负始终由服务器确认。
- 掉线检测由下一次玩家 action 触发。双方离线时没有后台时钟；回来后重新倒数。
- 显式离开由 `on_player_left` 结束比赛；关闭浏览器走离线暂停逻辑。live 内存状态在平台进程重启后无法恢复。
- 调整规则后更新 `playweft.json` 版本并创建新房间；不要改正在运行的对局参数。
- 规则和网络测试执行同一份 Lua 5.4 / Wasmoon 脚本，检查 50,000 条指令预算、碰撞、输入权限、重开、断线和重连。浏览器视觉验收及正式部署后的 Playweft 双设备验收尚未完成。
