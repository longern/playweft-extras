# 光尾蛇 · Light Trails

**控制方向，避开墙壁与光轨，生存至最后。**

- 触屏使用网页右下角的四向虚拟方向键，不受 16:9 赛场边界限制；键盘支持方向键或 `W` / `A` / `S` / `D`，均为绝对方向。
- 自动前进，每格最多转向 90°，连续猛点不能瞬间掉头。
- 撞墙、自己的尾迹或对手的尾迹判负；同时碰撞则平局。
- 三秒倒数，双方确认再来一局，累计比分。
- 支持旁观。短暂断线 / 切后台后暂停，恢复后倒数继续。

## 接入

源码目录为 `games/light-trails/`，开发和部署地址均为 `/light-trails/`。Manifest 使用两人房间、Lua 服务端和 `persistence: "live"`。客户端通信代码位于 `src/playweft-client.js`。

Manifest 顶层设置 `"orientation": "landscape"`，由 Playweft 请求横屏，必要时进入全屏后重试。浏览器可能不支持或拒绝锁定；游戏保留竖屏布局和旋转提示，不在 iframe 内重复申请全屏。实际赛场固定为 16:9，在 iframe 的安全区域内等比放大至宽或高的上限，并在水平、垂直方向居中；不裁剪、不拉伸。比分位于赛场浮层，方向键位于整个网页的安全区域内，不再占据左右栏。适配安全区域、矮屏和减少动画偏好。局内计时来自服务端已执行的步数，暂停时不计时。

界面版本为 `1.6.0`。部署后使用最新 Manifest 创建新房间，以应用横屏偏好和新版资源。

在仓库根目录运行 `npm run dev` 可与真正的 Playweft 平台一起开发；`npm run dev:light-trails` 启动独立开发联调工具。具体地址和构建命令见 [仓库说明](../../README.md)。

## 同步与规则参数

`game.lua` 顶部的 `WIDTH`、`HEIGHT`、`STEP_MS`、`COUNTDOWN_MS`、`STALE_MS` 分别控制地图宽高、前进步长、倒数和断线判定。当前参数是 48×27、180 ms / 格、三秒倒数和 1.8 秒离线阈值。调整地图大小时也需检查 `new_round` 的出生点；客户端从服务器状态读取地图大小和步长，无需单独修改这些常量。

Playweft live room 没有自动 tick，也不能使用 `timerOps`。双方各以 100 ms 间隔提交 `pulse`，每名玩家最多三个 pulse 在途，避免等待网络往返导致发送频率下降；转向单独立即提交。旁观者不发送 pulse。

Lua 按平台 `context.actionAt` 推进固定时间步，不信任客户端时间、坐标或身份。增加 pulse 次数不会加速游戏。先结算已到期的移动，再排队下一步转向，迟到输入不能改写过去。每一步先检查两人的目标格，再一起提交移动，避免座位顺序影响判定。

`steer` 输入携带 `seq`、绝对 `heading`（东 0、南 1、西 2、北 3）和目标 `tick`。客户端在下一个可显示的格点预测转向，不等待服务器回复。服务端取消固定 240 ms 提前量，按最早合法目标 tick 执行；迟到输入顺延，已经执行的步数不能改写，恶意远期请求最多排到当前 tick + 4。最多排队两个转向，避免连续操作积压成漫长延迟。已接受的双方转向立即广播给玩家和旁观者。重复序号不会重复执行，暂停和重开清空队列。

`sync.js` 保留有界本地预测（最多二至四格）并重放未确认输入。自己的播放时钟没有额外显示缓冲；按键只等待当前已经显示的路段走完，在下一格点转向，正常等待范围约 0–180 ms。服务器确认不同的执行时刻时仍需校正，不能保证所有网络下都在这个范围完成权威转向。自己的碰撞预测只使用已知实体轨迹，不凭猜测对手未来路径就把玩家挡住，也不自行判负。

对手根据已确认轨迹和已接受转向播放，使用 100–220 ms 的显示缓冲；未知直行最多外推一格，取消旧版三格猜测。新快照产生的位置误差在 100 ms 内逐渐消除，避免收包瞬间跳位置；已确认的完整障碍轨迹保持可见。严重缺包时停止有界预测，保持赛场可见；短暂缺包继续接受方向键，持续 400 ms 的异常才显示角落提示。自己的即时预测和对手缓冲存在时间差，突发转向、近距离交会与高延迟下仍可能校正，最终碰撞由服务器决定。

服务器在终局快照中提供每条撞击蛇的 `impact`（时刻、tick、起点、目标格、障碍类型与所属玩家），碰撞格不写入实体轨迹。客户端保留最后显示的位置，沿终局路径播放至接触位置（80–300 ms），再定格 200 ms 后显示比分与结果；此时控制已关闭，不改变胜负，也不允许撞后获救。迎头、交叉同格和交换头部位置使用双方运动计算视觉接触点。重复终局包或再战请求不重启动画，新局清除撞击状态。

## 已知限制与验证

- 1.6.0 优先修正输入响应：去掉固定排期，自己先预测、服务器确认；没有回滚改判，也不保证高延迟贴身躲避等同于单机。
- 掉线检测由下一次玩家 action 触发。双方离线时没有后台时钟；回来后重新倒数。
- 显式离开由 `on_player_left` 结束比赛；关闭浏览器走离线暂停逻辑。live 内存状态在平台进程重启后无法恢复。
- 调整规则后更新 `playweft.json` 版本并创建新房间；不要改正在运行的对局参数。
- 规则和网络测试执行同一份 Lua 5.4 / Wasmoon 脚本；双人加旁观者的真实 WebSocket 测试同时覆盖正常链路及 160–360 ms 往返延迟与有序突发消息，逐帧转向测试覆盖 200 ms RTT 下不同按键时机，测量无需回复的输入到转向时间，并与真实 Lua 执行结果对照；另外检查确认后的校正、迟到转向、已知碰撞与队列上限；检查 50,000 条指令预算、碰撞、输入权限、重开、断线和重连。浏览器视觉验收及正式部署后的 Playweft 双设备验收尚未完成。
