# 光尾蛇 · Light Trails

**左右转向，别撞墙和任何尾迹。活到最后的人赢。**

- 两按钮：左转 / 右转；键盘支持 `←` / `→` 或 `A` / `D`。
- 自动前进，每格最多转向 90°，连续猛点不能瞬间掉头。
- 撞墙、自己的尾迹或对手的尾迹判负；同时碰撞则平局。
- 三秒倒数，双方确认再来一局，累计比分。
- 支持旁观。短暂断线 / 切后台后暂停，恢复后倒数继续。

## 接入

源码目录为 `games/light-trails/`，开发和部署地址均为 `/light-trails/`。Manifest 使用两人房间、Lua 服务端和 `persistence: "live"`。客户端通信代码位于 `src/playweft-client.js`。

在仓库根目录运行 `npm run dev` 可与真正的 Playweft 平台一起开发；`npm run dev:light-trails` 启动独立开发联调工具。具体地址和构建命令见 [仓库说明](../../README.md)。

## 同步与规则参数

`game.lua` 顶部的 `SIZE`、`STEP_MS`、`COUNTDOWN_MS`、`STALE_MS` 分别控制地图大小、前进步长、倒数和断线判定。当前参数是 40×40、120 ms / 格、三秒倒数和 1.8 秒离线阈值。调整地图大小时也需检查 `new_round` 的出生点；客户端从服务器状态读取地图大小和步长，无需单独修改这些常量。

Playweft live room 没有自动 tick，也不能使用 `timerOps`。双方各以 100 ms 间隔提交 `pulse`，每名玩家最多一个 pulse 在途；转向单独立即提交。旁观者不发送 pulse。

Lua 按平台 `context.actionAt` 推进固定时间步，不信任客户端时间、坐标或身份。增加 pulse 次数不会加速游戏。先结算已到期的移动，再排队下一步转向，迟到输入不能改写过去。每一步先检查两人的目标格，再一起提交移动，避免座位顺序影响判定。

客户端在已经确认的相邻格之间插值，视觉最多落后一格，不预测碰撞结果。碰撞地图编码为 40 行字符串，轨迹使用格子编号数组；`view` 隐藏地图、在线记录和对手尚未执行的转向。

## 已知限制与验证

- 这是休闲实时联机演示；高延迟会影响操作手感，尚未加入预测和延迟补偿。
- 掉线检测由下一次玩家 action 触发。双方离线时没有后台时钟；回来后重新倒数。
- 显式离开由 `on_player_left` 结束比赛；关闭浏览器走离线暂停逻辑。live 内存状态在平台进程重启后无法恢复。
- 调整规则后更新 `playweft.json` 版本并创建新房间；不要改正在运行的对局参数。
- 规则和网络测试执行同一份 Lua 5.4 / Wasmoon 脚本，检查 50,000 条指令预算、碰撞、输入权限、重开、断线和重连。浏览器视觉验收及正式部署后的 Playweft 双设备验收尚未完成。
